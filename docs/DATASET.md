# Dataset — UNSW-NB15 (as supplied)

Full machine-generated profiling lives in [dataset_analysis.md](dataset_analysis.md) and `ml/artifacts/metrics/dataset_profile.json`; this page summarizes it and states clearly what the data does **not** contain.

## What was supplied

| Split | Rows | Columns | Attack ratio |
|---|---|---|---|
| `UNSW_NB15_training-set.csv` | 175,341 | 45 | 68.1% (119,341 attacks) |
| `UNSW_NB15_testing-set.csv` | 82,332 | 45 | 55.1% (45,332 attacks) |

Schema matches across splits; 0 duplicate rows; 0 missing values; 0 infinite values (after the pipeline's inf→NaN→train-median sanitization); 0 label↔category mismatches. Both splits carry 9 attack categories plus Normal; no category appears in only one split. The multiclass problem is heavily imbalanced — Worms has 130 train / 44 test rows vs Generic's 40,000 / 18,871 (≈431:1 max/min in train).

Three categoricals: `proto` (133 train values), `service` (13), `state` (9). `is_ftp_login` is documented as boolean but contains {0,1,2,4} — treated as ordinal numeric.

## What is NOT in the data (non-negotiable honesty)

The supplied 45-column CSVs are pre-aggregated flow records. They contain:

- **No `srcip`, `sport`, `dstip`, `dsport`** — no IP addresses or port pairs, therefore no real hosts, networks, or geolocation.
- **No timestamps** — no capture time of any kind.
- **No user or device identity** — no accounts, hostnames, or asset inventory.

Everything time- or entity-shaped in this product is therefore **clearly-labeled simulation**: replay timestamps are synthetic offsets generated by the training pipeline (`ml/artifacts/replay/demo_sequence.json`, `"label": "Real-Time Detection Replay (SIMULATED timestamps)"`), and `ENT-*` pseudo-entities are deterministic hashes of flow-level attributes (see [INCIDENT_CORRELATION.md](INCIDENT_CORRELATION.md)). The UI renders both with violet "SIM" tags, and LLM prompts instruct the model never to invent IPs, users, or CVEs. UNSW-NB15 itself is synthetic lab traffic captured in 2015 — it is **not** phishing, malware-file, or real-enterprise telemetry.

## Split quirks that matter

1. **`id` is not globally unique.** Each official file numbers `id` from 1, so all 82,332 test ids numerically collide with train ids. `id` is excluded from features (as are `label`/`attack_cat`, the targets); row content is the official disjoint split.
2. **Two unseen `state` values in test** — `ACC` and `CLO` never occur in training. The encoder maps any unseen category to a dedicated `__unknown__` bucket (code = train cardinality), so the engine degrades gracefully instead of crashing or silently mis-encoding.
3. **Distribution shift.** Test's attack mix differs from train (e.g., DoS 12,264→4,089; Worms 130→44), and the binary label base rate drops from 68.1% to 55.1% — realistic conditions for the one-shot test evaluation.

## Feature engineering implications

39 raw numeric columns are used; the 24 with |skew| > 3 in training (e.g., `sbytes` skew 45.3, `spkts` 40.2) get `log1p`; 12 derived ratios (`byte_ratio`, `packet_ratio`, `load_ratio`, `flow_asymmetry`, …) and 3 encoded categoricals complete the 54-feature vector. All preprocessing statistics (medians, skew selection, category maps) are fitted on the training split only. The ablation study shows the derived features add +0.0011 validation F1 over raw-only (0.9725 → 0.9736) — the engineering is for interpretability and robustness more than raw accuracy ([EVALUATION.md](EVALUATION.md)).
